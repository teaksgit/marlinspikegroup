Marlinspike Family Office Dashboard

Security and Data Handling

Last updated: August 31, 2026

This statement describes how the Marlinspike Family Office Dashboard (the "Application"), operated by Marlinspike Group LLC, protects the data it holds, including data read from QuickBooks Online. It is the reference document for our QuickBooks Online integration review.

1. Application profile

  • Private, single-owner internal application. No public sign-up and no unrelated tenants.
  • Accounts are created only by an administrator. There is no self-registration and no anonymous access.
  • All authorized users belong to the owner's own organization.

2. Authentication and access control

  • Email and password authentication provided by a managed authentication service.
  • Time-based one-time-password multi-factor authentication is supported, and is required for administrator accounts.
  • Passwords are checked against known-breached password lists at the time they are set.
  • Repeated failed sign-in attempts trigger a temporary lockout.
  • Sessions terminate automatically after a period of inactivity.
  • Role-based access control separates administrator, standard, and read-only roles. Roles are stored server-side in a dedicated table and evaluated by server-side functions; they cannot be changed from the browser.
  • Only administrators can connect a QuickBooks company file, run a sync, edit category mappings, or recategorize transactions.

3. Data protection

  • All traffic between the browser, the application backend, and Intuit's APIs uses HTTPS/TLS.
  • Data is stored in a managed PostgreSQL database with encryption at rest provided by the hosting platform.
  • Every table holding financial data has row-level security enabled, with policies that limit each request to the entities the requesting user is authorized to see.
  • Database backups are managed by the hosting platform and are subject to the same access restrictions.

4. QuickBooks Online data scope

The Application requests a single OAuth scope, com.intuit.quickbooks.accounting, and uses it for reading only. It never writes, updates, or deletes data in QuickBooks Online.

Data read and stored:

  • Company name and realm identifier of each connected company file.
  • Chart of accounts: account name, fully qualified name, type, subtype, classification, active flag.
  • Expense and journal transaction lines: date, transaction type, document number, vendor or payee name, memo, account, and amount.

Data explicitly not requested or stored:

  • Payroll data and employee records.
  • Customer contact information.
  • Bank account numbers, routing numbers, and payment card data.
  • Any Intuit user credentials. Authentication happens entirely on Intuit's own pages.

5. OAuth token handling

  • The authorization code exchange happens entirely server-side, in a backend function. The authorization code, client ID, and client secret are never present in browser code.
  • Access and refresh tokens are stored in a dedicated server-side table that grants no privileges to browser-facing roles. The table is reachable only by the backend service identity, so tokens cannot be read by any signed-in user through the client API.
  • Tokens are never written to application logs, error messages, or analytics.
  • The OAuth client ID and client secret are held in the platform's encrypted secret store and exposed only as environment variables to backend functions.
  • The state parameter is HMAC-signed server-side and expires after 30 minutes. Callbacks with a missing, tampered, or expired state are rejected before any token exchange. Post-authorization return URLs are restricted to an allow-list of our own origins.
  • Access tokens are refreshed automatically using the stored refresh token; no manual re-entry occurs.

6. Revocation and deletion

  • An administrator can disconnect a company file in the Application, which deletes the stored access and refresh tokens for that company.
  • Access can also be revoked at any time from Intuit's own account settings, which immediately ends the Application's ability to read that company file.
  • Synced accounting data can be deleted by an administrator at any time.

7. Logging and monitoring

Sign-in events, page views, and administrative actions are recorded for security review. Backend function logs record request outcomes and errors; they are deliberately written so as not to include tokens, secrets, or credentials. An internal audit view flags unexpected changes in recorded financial values for human review.

8. Third-party processors

  • Application and database hosting provider — hosting, database, storage, backups.
  • Intuit Inc. — source of authorized QuickBooks Online data.
  • AI service provider — receives only the data needed to answer a question an authorized user asks the built-in advisor, and is contractually restricted from using it for model training.
  • Market data providers — receive security identifiers only, never account or entity data.

9. Incident handling

Suspected security issues are investigated by the owner's administrator. Where an incident affects data obtained from QuickBooks Online, we will revoke the affected connection, rotate the affected credentials, and notify Intuit and any affected individuals as required by applicable law.

10. Scope of these statements

We do not claim any third-party security certification or audit report for this Application, and none is implied by this statement. It describes the controls implemented in the Application as of the date above.

11. Reporting a security concern

Please report suspected vulnerabilities or security concerns to pshah@marlinspikegroup.com. We aim to acknowledge reports within five business days.
